# V1.1 Web Bot Auth Registry-02 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Align ATI's experimental Web Bot Auth implementation with the currently published IETF registry-02, directory-05, architecture-05 and RFC 9421 contracts without changing V0/V1 privacy, scoring, or offline-default behavior.

**Architecture:** Preserve the existing `VerificationContext`, evidence model, resolver, source cache and `WebBotAuthVerifier`. Replace only the non-conformant Agent Card profile, split strict Directory-05 JWK semantics from generic registry-02 inline `keys`, add optional directory-response key binding verification, and keep Cloudflare's deployed structured-string syntax as an explicit legacy profile.

**Tech Stack:** Python 3.11+, RFC 9421 through the existing optional `http-message-signatures` adapter, standard-library JSON/URL handling, current source cache/fetcher, pytest/Hypothesis/Ruff/Mypy, GitHub Actions.

## Global Constraints

- V0 output remains byte-shape compatible when verification is disabled.
- `automation_score`, `ai_score`, `identity_confidence`, and `risk_score` remain independent.
- Verification never directly changes automation/AI/risk scores.
- Raw source IPs, signature bytes, Authorization, cookies, private keys, and sensitive request material never enter persisted detections.
- `ati analyze` remains offline by default and never refreshes sources implicitly.
- `UNAVAILABLE`, `STALE`, and `ERROR` never become `FAILED` by themselves.
- Core install keeps zero runtime dependencies; cryptography remains in `[verification]`.
- Deterministic PR CI performs no live DNS/HTTP calls.
- Current standards pins: RFC 9421, architecture-05, directory-05, registry-02, JAFAR-00.
