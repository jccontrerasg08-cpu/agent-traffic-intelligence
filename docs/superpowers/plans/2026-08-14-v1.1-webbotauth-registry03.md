# V1.1 Current Web Bot Auth Alignment Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Close the real interoperability and trust gaps around registry-03/CIMD, Directory-05 and deployed Cloudflare Web Bot Auth while preserving V0/V1 guarantees.

**Architecture:** Keep V1's existing CIMD Agent Card parser and verification resolver. Add narrowly scoped adapters for generic JWK Set parsing, strict client-id retrieval, CIMD Signature-Agent discovery, delegated-directory response binding and offline data-card parsing. Provider differences remain declarative and no new network access is implicit.

**Tech Stack:** Python 3.11+, RFC 9421 through ATI's existing optional `http-message-signatures` adapter, standard library JSON/URL/data URI handling, existing source cache/fetcher, pytest/Hypothesis/Ruff/Mypy, GitHub Actions.

## Global Constraints

- Current Agent Card profile is `draft-meunier-webbotauth-registry-03`.
- V0 output remains unchanged when verification is disabled.
- Verification directly changes only `identity_confidence`, never automation/AI/risk scores.
- Raw source IPs, signature bytes, Authorization, cookie values and private keys never enter persisted output.
- `ati analyze` remains offline by default and never refreshes sources implicitly.
- `UNAVAILABLE`, `STALE` and operational `ERROR` never become `FAILED` by themselves.
- Core stays zero-runtime-dependency; crypto remains in `[verification]`.
- PR CI remains hermetic with no live DNS/HTTP.
- Maintain normally no more than 2–3 active PRs; implement all V1.1 work in PR #8.
