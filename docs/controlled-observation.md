# Controlled Observation Campaigns

A controlled observation campaign creates **ground-truth labels** for traffic generated by an agent that you authorize. It measures whether ATI recognizes a known automated request under a defined configuration. It does not prove the identity, intent, safety, or authorization of third-party traffic.

## Privacy contract

Use one opaque, non-secret marker per campaign. Configure the access-log adapter to write that marker to the JSON field `ati_campaign_id`; a common source is an allowlisted request header such as `X-ATI-Experiment-ID`. The marker must not be an API key, bearer token, email address, account identifier, query parameter, cookie, request body, or value reused outside the campaign.

ATI reads only `ati_campaign_id` to select controlled records. Generated labels contain `request_id`, `automated`, `label_source`, `label_confidence`, and `corpus_id`; they intentionally do **not** retain the campaign marker, raw IP address, query string, cookies, `Authorization` header, request body, or arbitrary request headers.

> The campaign marker is a ground-truth signal that you control. It is not cryptographic proof that an external bot is genuine. Continue using verified provider evidence separately for third-party attribution.

## Prepare the site

Choose a unique marker such as `owned-shadow-2026-08-19-a`. Tell the controlled agent to send that exact value only in `X-ATI-Experiment-ID` while visiting owned, allowed paths at an approved rate. Configure the proxy or application logger to map that header to the JSON field `ati_campaign_id` and to retain the normal privacy-safe access fields already accepted by ATI.

For an Nginx JSONL adapter, the relevant field is conceptually:

```json
{"time_iso8601":"...","remote_addr":"...","request_method":"GET","request_uri":"/allowed-path","status":200,"body_bytes_sent":123,"http_user_agent":"ControlledAgent/1.0","ati_campaign_id":"owned-shadow-2026-08-19-a"}
```

Do not log the complete header set merely to support this feature. The adapter should emit only `ati_campaign_id` and the existing allowlisted access fields.

## Run a campaign

Create a local manifest before using outputs for any benchmark, threshold, or model decision. The manifest remains local and uses the existing authorized-corpus format from [evaluation.md](evaluation.md). Set its `corpus_id` to a non-sensitive name, record the actual collection window, and declare `controlled-traffic-overrepresentation` as a known sampling bias.

After the controlled agent has visited the site and the access log is available locally, generate only the matching ground-truth labels:

```bash
export ATI_HASH_KEY='a-long-local-secret'
ati campaign labels access.jsonl \
  --campaign-id 'owned-shadow-2026-08-19-a' \
  --corpus-id 'owned-shadow-2026-08' \
  --output labels.jsonl
```

The command reports `generated_label_count` on standard error. Stop and investigate the proxy field mapping, marker, collection window, and source log if this count is zero or unexpectedly low.

Analyze and evaluate the same immutable input with the same hash key:

```bash
ati run access.jsonl \
  --run-dir runs/owned-shadow-2026-08 \
  --labels labels.jsonl \
  --manifest corpus-manifest.json \
  --source nginx
```

A successful run creates only `detections.jsonl`, `evaluation.json`, `run.json`, and `summary.md`. It does not copy the access log, labels, manifest, campaign marker, or raw identifiers into the artifact directory.

## Decide whether the observation is usable

The run is ready for review only when `summary.md` reports `Quality status: ready`, `generated_label_count` matches the authorized campaign request count, and the collection window contains both controlled and representative non-controlled traffic. A campaign consisting only of your own agent is useful for a conformance check, but it is not sufficient to train or calibrate a general model.

Keep raw logs and manifests outside version control. Rotate the campaign marker for each run, retain data for the minimum approved period, and delete local diagnostic inputs according to your retention policy after the evaluation is complete.
